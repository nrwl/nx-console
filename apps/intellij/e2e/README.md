# IntelliJ E2E tests

Run commands from the repository root. The project-view test builds this
checkout, launches IntelliJ in a fresh sandbox, and checks that Nx Console shows
the fixture's `demo` project and `hello` target. It records the run and cleans up
its IDE, fixture, and sandbox when finished.

## Prerequisites

- macOS with a logged-in desktop session, or Linux. Windows is not supported.
- The Node.js version in [`.nvmrc`](../../../.nvmrc), with Corepack enabled.
- A Java 21 JDK, with `JAVA_HOME` pointing to it and Java available on `PATH`.
- Git and `ffmpeg` with the `libx264` encoder available on `PATH`.
- An activated `idea.key` compatible with the repository's pinned IntelliJ IDEA
  Ultimate version. The runner downloads the IDE; a separate IDE installation
  is not required to run the test.

Install the workspace dependencies:

```sh
corepack enable
yarn install --immutable
```

On macOS, install `ffmpeg`, for example with Homebrew:

```sh
brew install ffmpeg
```

On Ubuntu 22.04, install the JDK, recording tools, and GUI libraries:

```sh
sudo apt-get update
sudo apt-get install -y openjdk-21-jdk git procps xvfb ffmpeg fonts-dejavu-core \
  libasound2 libnss3 libxkbfile1 libx11-6 libxi6 libxtst6 libxrender1 \
  libxrandr2 libglib2.0-0 libdbus-1-3 libgbm1
```

Linux runs create their own Xvfb display, so no desktop session or manual
`DISPLAY` configuration is needed. Keep Java graphics enabled; setting
`java.awt.headless=true` prevents the UI from rendering.

## License and run

Point the runner to an activated key file outside the repository:

```sh
export NX_INTELLIJ_LICENSE_FILE=/absolute/path/to/idea.key
```

Use the `idea.key` generated by offline activation in the IDE's configuration
directory. Signing into another IDE with a JetBrains Account does not activate
the test's fresh sandbox. See the [automation guide](../AUTOMATION.md#run-the-project-view-e2e-test)
for instructions on obtaining the file. The runner copies the key into its
temporary sandbox and removes that copy at shutdown.

Run the individual test:

```sh
CI=true NX_NO_CLOUD=true NX_DAEMON=false NX_PLUGIN_NO_TIMEOUTS=true \
  yarn nx run intellij:e2e-ci--project-view
```

`intellij:e2e` runs all IntelliJ E2E tests. `NX_NO_CLOUD=true` keeps local runs
off Nx Cloud while retaining Nx's local cache. The first run downloads IntelliJ,
its plugins, and Gradle dependencies and can take several minutes.

## Results and recordings

Evidence is written to `dist/apps/intellij/e2e/latest`: `result.json`,
`junit.xml`, logs, UI inspection files, and an MP4 recording. A failed test exits
with a nonzero status. Linux records startup as well as the scenario; macOS
recording starts after the automation client connects to the fixture.

Unchanged inputs restore the cached result and its original evidence. Append
`--skip-nx-cache` to the command when you need a fresh run and recording. Each
execution replaces `latest`, so copy that directory elsewhere before recording
another run if you want to retain both.

To exercise failure reporting, set `NX_E2E_EXPECTED_PROJECT=missing-project`
when running the test; it should fail and save evidence.
